## 存储与扫描的设计

沿用SQLite与现有works/tag/阅读状态，不另建同内容数据库。新增目录库、文件项、扫描记录和阅读缓存表，明确区分作品身份、物理文件位置与缓存。目录库使用容器内绝对根路径，文件项使用库内相对路径；读取前校验所属根目录与符号链接，禁止越界。托管文件仍沿用现有可移植路径规则，外部源保持独立定位。

扫描按目录流式遍历，先比较大小/mtime等版本信息，变化才读取ZIP目录、ComicInfo与封面。保留压缩页面清单，避免大库在扫描时为每个页面生成数据库行；现有托管work_pages兼容，外部作品按清单提供阅读索引。持久封面保存经过尺寸限制的JPEG，按需复用现有缩略图接口。网络IO不占用SQLite写事务。

文件项有待稳定、可用、损坏/不支持、暂不可用等状态。文件处理前后核对版本，变化则重试；每项失败隔离，错误样本与任务日志有数量上限。只有完整成功遍历才能确认缺失；挂载空目录/设备改变/扫描中断保留既有索引、封面、标签、收藏和进度。移除库默认只移除注册/索引关联，绝不删除外部文件。

挂载源按阅读需求进入本地归档缓存：流式复制到临时文件、校验源未变化与ZIP可读后原子发布；同部只下载一次。配额与空闲期限只清理本应用拥有且未在用的缓存，空间不足返回明确状态。托管/本地库默认直接读，挂载库默认缓存；管理员可调策略。元数据/封面占用与可回收阅读缓存分开显示。

复用已安装的watchfiles原生事件与现有任务生命周期；定期补偿轮询适应FUSE不发事件的情况，暂停/取消和重启恢复不另造任务框架。rclone自身目录缓存与polling也决定可见性，设置/部署文档给出对应说明；应用不凭一次空列表自动删除作品。[rclone挂载文档](https://rclone.org/commands/rclone_mount/)、[远程控制文档](https://rclone.org/rc/)是兼容性依据。

## 刮削、订阅与邮件的设计

扩展现有MetadataRefreshService，复用预览/应用、真实V2查询与tag持久化。评分展示证据：ID/ComicInfo、标题、页数、作者/社团、语言及候选差距；语言硬约束不能仅靠排序。自动应用只接受唯一强匹配，人工名称/ID选择同样在服务端重新验证；已手改字段不被静默覆盖。刮削与绑定可分别控制。

订阅以真实remote tag ID与artist/group类型识别，不以可改中文名作主键。检查使用日期排序与分页，持久化已见作品和通知去重约束；基线/游标在完整成功检查后推进，429遵守Retry-After，失败不推进。站内更新独立于SMTP，可追溯订阅/作品/发现时间。

SMTP使用Python标准库email/smtplib与TLS证书校验，凭据沿用现有设置私密值/公开配置状态约定。持久待发送记录和重试状态避免重启丢通知；邮件仅包含真实更新，链接与标题安全编码。自动通知取决于用户启用的订阅与邮件配置；开发验证使用本机SMTP接收器，不向真实第三方地址发送。

官方[changelog](https://nhentai.net/api/v2/changelog)已于本轮直接只读读取，最新章节2026-10-06；常规浏览工具失败，HTTP请求返回200。已确认batch tag lookup、V2下载入口及429退避与现有代码一致；最新taxonomy示例/审核及用户permissions可评估用于词典证据/连接状态，不属于作者订阅必需接口。接口具体参数还要以官方docs/OpenAPI核对，禁止猜测“订阅API”存在。
