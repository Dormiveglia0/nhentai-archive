# 前端重新设计规划

状态：2026-09-22，规划稿，尚未实施、尚未获得视觉认可。94e5364 的页面方案被用户否定。设置页、阅读器底部悬浮操作、库作品详情来源浮层保留。本文优先于旧文档中将上一轮页面称为设计基准的描述。

## 1. 问题判断

上一版把设置页的局部表现形式误当成整站方法：每页都出现大型分类卡、倾斜、纸片阴影。结果是阅读类页面作品下沉，管理类页面空状态占满首屏，分类改变后整个布局迁移，用户失去操作位置。首页的柱状图又把稀疏数据放大为大片空白，没有形成首页应有的整体构图。

设置页的可取之处：六类同等级配置适合先总览后进入，图形让模块可识别，选中与展开有关系。不应据此推断用户喜欢所有倾斜纸卡、所有配色细节、所有横向位移。

核心决定：按页面行为设计结构。统一尺度、材料、对齐、交互状态和运动规则；展示、浏览、处理三类页面分别排版。

## 2. 内容优先级

| 页面 | 用户到达时首先要看到 | 首个主要操作 | 应退到次级的信息 |
| --- | --- | --- | --- |
| 首页 | 有整体构图的互动场景，能辨识与阅读有关 | 探索某个阅读节点，或观看场景响应 | 完整报表、作品长列表、重复导航 |
| 我的库 | 当前作品、阅读入口 | 选作品或筛选 | 分类计数、管理动作 |
| 发现 | 热门作品的差异、可继续浏览的结果 | 看详情、搜索 | 完整元数据、导入状态细节 |
| 队列 | 正在运行和需要处理的任务 | 查看进度、处理异常 | 已结束记录、空状态分组 |
| 治理 | 当前作品、需要核对的差异 | 比较并采纳一个值 | 装饰封面、完整来源诊断 |
| 词典 | 可检索的原文与译文 | 定位词条并编辑 | 大型类别图形、重复计数 |
| 文件 | 文件清单、异常和占用 | 定位文件、预览处理影响 | 大型文件夹插画 |
| 导出 | 已选作品、输出内容和文件名 | 选择并配置导出 | 大号步骤编号 |
| 设置 | 六类配置对象 | 进入相应配置 | 保持现有实现 |
| 登录 | 一个明确、私密的访问入口 | 输入密码 | 第二个重复品牌、大块装饰 |

## 3. 统一布局约束

- 不新增面向用户的设计说明、欢迎词、装饰性英文编号或自创页面名称。
- 顶栏高度和主导航位置稳定；不为制造动效而再次变换整站导航结构。
- 浏览页的标题、搜索、常用筛选总高度以桌面 120–160px 为起始预算；不能由大型统计卡占据半屏。
- 分类选中只更新选中状态与内容，不从横向变纵向、不重新定位搜索框。是否展开详情属于另一种明确操作。
- 大屏增加有效内容宽度和比较空间；封面设尺寸上限。不能把所有内容居中缩成一团，也不能等比例放大所有按钮和文字。
- 内容宽度按功能区别处理：库/发现可宽，表单和长文本需限宽；不是全站套一个宽度。
- 阴影只用于浮层和真实层级，透视只用于首页主场景及已认可的设置对象。普通表格、筛选、输入框保持平面。
- 一个页面最多一个持续运动的视觉中心。文字区、输入区和滚动列表不持续漂动。

## 4. 页面构图

### 首页

方向：一个完整互动场景与小面积上下文信息结合，取消当前巨大图表、重复统计卡和最近作品横条的拼盘。

桌面主场景占可用内容宽度约 70%–76%；侧面约 24%–30% 是随选择更新的阅读信息。整体在一个视口内形成构图，场景和文字共享基线，不依靠大标题支撑。侧面不是永远空置的详情栏：未选中时展示期间总览，选中时展示该节点的日期、时长、阅读次数和实际关联作品。

主场景候选构图：以真实阅读事件的先后形成一条连续路径，节点表示事件或明确时间段。静止状态已经能看清主线与疏密；指向节点时，邻近线段改变张力，当前节点抬起，信息同步；展开后主场景让出阅读空间，原节点保留位置关系。封面只在明确选中相关作品时作为辅助，不作为整页主视觉。

注意：这不是沿用旧 Echo 三栏图，也不在本轮直接实现。先画出无选择、指向、展开三帧，证明没有右侧测试开关、没有标题堆砌，且少记录时仍有完整构图。只有日期聚合数据时只能表示日期，不伪装成精确阅读事件；事件级表现须先核实真实历史 API 粒度。作者或标签关系仅在可靠实际关联存在时出现，不用低辨识度标签强行连接。

稀疏状态：缩短有效路径、保留结构基线，不复制节点和虚构读数；完全空时使用与阅读有关的抽象页形表现，但与真实数据节点有明确视觉区别。空状态不假装有阅读活动。

### 我的库

首屏结构：紧凑页名/数量 → 同一行搜索与常用筛选 → 作品区。全部、未读、在读、已读使用固定位置的小型状态切换，计数为辅助，不再做四张大卡片。

继续阅读、最近添加和全部作品作为同一浏览区域的固定切换。切换后控制区位置不变。作品封面是视觉主体；信息分为标题、作者/语言、进度，标签限制高度，批量动作在选择时出现。

保留封面来源浮层；hover 表达可选状态但不出现“进入阅读”遮罩。作品数量少时自然靠齐，不拉大填满；多行封面与元信息分别对齐，不用行高拉伸卡片。

### 发现

首屏分上下两层：热门构图约占桌面可用高度 35%–42%，下方首批普通结果必须可见。热门展示一部主要作品和相邻预览，选择位置固定，通过封面、标题和相邻关系的共同变化解释切换。

不能仅因指针穿过移动封面就连续换选。明确的点击、键盘或手势驱动作品切换；hover 只预告可操作。主作品尺寸设上限，大屏增加相邻作品可见范围和资料空间。搜索与筛选不跟随热门重排。完整封面适配策略独立验证横竖比例，不再产生竖封面空缝。

### 队列

使用任务优先的构图：上方一条紧凑状态概览，下方左侧任务列表、右侧选中任务的进度与日志。列表与详情的视觉权重约 55:45，依据日志内容调整。

运行任务和异常任务优先可辨识，已完成任务为较低对比度记录。没有任务的状态只保留计数，不生成四张大空卡。进度更新只改变实际进度，不重播整页动画；日志刷新不闪白。手机由列表进入详情，关闭返回原任务与滚动位置。

### 治理

采用比较工作区：一条紧凑作品身份栏，左侧是待处理项目/字段导航，主体是来源与最终值比较，右侧或底部保留更改摘要与保存。封面只是识别符号，不占三百像素高的首要区域。

短字段可以并排比较，长标题和简介根据可读行宽使用上下对照，避免三列窄长文本。采纳动作让对应来源和值框建立短距离反馈，草稿立即生效。没有改动时不以巨大固定栏压住正文。

### 词典

使用高密度索引与就地编辑：搜索和类型过滤固定；列表按原文、译文、影响范围、状态对齐。一个词条不需要一张占半屏宽的卡片。

选中行保留位置，编辑区从该行对应方向打开，附近行仍可辨识。批量导入作为独立工具入口。长原文、译文缺失、0 部作品和无结果都要进入设计稿，而不只画理想短词。

### 文件

页面以清单为主体。容量与异常压缩为头部细条，全部/作品/孤立/临时是紧凑过滤。选中行展开文件详情，路径、体积、状态、预览删除影响各有固定位置。

扫描与清理独立成维护区域，不与普通浏览抢首屏。高风险操作继续先预览再确认；动效不能模糊“选中”“预览”“实际删除”的区别。

### 导出

桌面采用“作品选择 + 打包预览”双区同时可见。左侧选择源作品，右侧清楚显示输出名称、包含内容、压缩选项和下载动作。已选数量和输出变化就地反馈，不要求用户反复在两张步骤卡之间切换。

手机使用顺序步骤，但保持配置与已选作品。打包动效围绕真正加入/移除的内容发生，不能用盒子装饰代替名称、体积和错误提示。

### 登录、历史、远端详情

登录只保留一处品牌和一组输入控件。使用与站内同一材料与字阶的独立入口，不加巨型 NH 加小 NH 的重复构图。背景不显示登录后页面。提交、错误、成功分别规划；成功衔接顶部导航的真实位置。

历史以真实日期和具体时刻组成连续记录，不用同一个月日重复充当唯一标识。远端详情以识别作品、阅读/导入、页面预览三层组织；不重新引入大封面挤占操作的结构。阅读器已认可控件保留。

## 5. 动效设计应先于动效代码

| 操作 | 应发生的运动 | 保持不动的内容 |
| --- | --- | --- |
| 页面切换 | 当前内容退场、下一页主要区域有一次短衔接 | 顶栏、焦点规则、可滚动视口 |
| 分类筛选 | 选中指示移动，结果局部更新 | 搜索框、分类位置、页名 |
| 作品展开 | 封面从来源位置连续进入详情，文字随后出现 | 相邻作品的基本排布 |
| 任务选择 | 所选行与详情标题建立对应，进度连续 | 列表滚动位置、日志历史 |
| 采纳字段 | 来源对应反馈、目标框确认 | 其他字段和输入焦点 |
| 首页探索 | 邻近响应、选中节点、空间让位依次发生 | 数据含义与节点身份 |
| 登录成功 | 输入完成反馈 → 场景收束 → 顶栏就位 → 内容显现 | 验证结果与用户输入状态 |

时长是待实测的预算：局部反馈约 120–180ms，区域变化约 220–320ms，主场景展开约 400–600ms；不全站机械套用同一个 spring。关闭或反向选择接续当前位置，不排队。持续动效离屏/后台停止；减少动态效果时仍能理解选中状态。

## 6. 进入实施前需要形成的设计材料

1. 首页、库、队列三类代表页的灰阶布局，标明首屏边界、真实信息数量、主要操作和滚动区域。先判断比例，不加阴影掩盖问题。
2. 同三页的视觉定稿，以及 2560×1440、1440×1000、390×844 的对应构图。其余页面根据上述各自任务单独出布局，不照搬代表页。
3. 首页探索、库详情、任务选择和登录成功的关键帧：初始、反馈、过渡中、完成、反向。每一帧都有可解释的位置关系。
4. 空数据、稀疏数据、长标题、多任务、错误和加载状态的补充图。
5. 先检查设计方向再改正式路由；不能再用“构建通过/没有溢出”代替视觉验收。

## 2026-09-22 · 库页面第二轮构图

用户认为第一轮库网格单调。评审页的库章节新增两层书架构图：上方约250px的续读近景，由真实在读作品形成层次；下方保留平面作品矩阵。近景不加入统计卡，不依赖hover自动换选。无续读记录时取消近景，不填假作品；作品少时不拉伸。补充来源详情展开、390px手机浏览与详情两状态图。仍为设计稿，尚未实施。近景会减少首屏矩阵数量，这是本方案需评估的明确取舍。

## 2026-09-22 · 续读信息优先级修订

用户明确：继续阅读区域右侧 tag 比标题重要。设计稿改为标签 → 次级标题 → 阅读进度。桌面优先提供两行可读、可点击的内容/题材标签及展开全部入口，标题以较低对比度最多两行显示；作者、社团、语言不能挤占内容标签的主要空间。此条已由下方移动端专门约定覆盖：手机续读区不设置独立标签展示。图中“内容标签”为结构占位，不是硬编码候选；正式实现必须使用作品真实标签与已有翻译，无标签时诚实显示缺失。现有来源详情浮层布局本轮不变。

## 2026-09-22 · 移动端续读区精简

用户明确桌面信息补充不应直接搬到手机。桌面保留续读右侧的标签优先区；手机删除续读作品的独立标签/标题详情块，仅保留封面与轻量阅读进度，将作品矩阵上移。标签仍可在作品详情中查看，下方普通作品条目的原信息布局不因此全部删除。响应式设计按空间和使用场景分配信息，不以桌面模块逐一堆叠为目标。此次仅更新设计稿。
